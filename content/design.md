# Design Direction

*Visual direction and design tokens for the site. Values marked `[PLACEHOLDER]` are pending — fill in as decisions are finalized, don't infer them.*

## Philosophy
- Simple, minimalistic, clean
- Generous spacing, restrained color palette
- No template-like layouts, nothing generic or "camp"
- Not overly formal or corporate — should feel bespoke, not templated
- Micro-interactions (hover / press) add polish without becoming decoration
- Motion is intentional, never decorative for its own sake
- Mobile and desktop should feel like one coherent system, not two separate designs

- `button-gap`: `16px` — gap between adjacent buttons in a row (currently the Testimonials filter buttons)

### Mobile token overrides (`<768px`)
Per the user: type and spacing tokens should step down on mobile rather than staying fixed across every breakpoint — everything above was defined once and used everywhere, but on a narrow phone screen the full-size values read as too generous. Implemented as a single `@media (max-width: 767px) { :root { ... } }` block in `globals.css`, placed after the `@theme` block and (like `background-primary` etc.) deliberately **not** inside any `@layer` — Tailwind v4's `@theme` tokens compile to real CSS custom properties inside a named layer, and unlayered rules always win the cascade over layered ones regardless of source order, so this one override point reaches every component that uses `text-body`, `px-page-y`, `gap-button-gap`, etc. without touching component files individually — the same "change it once" principle the rest of the token system follows.
- Font: `nav` 20→16px, `body` 24→20px, `caption` 16→12px, `title` 32→28px (each step given directly by the user; `title`'s wasn't part of the general rule below since 32px doesn't fit that scale, so it was asked for and given separately)
- Spacing: `page-x` 32→20px, `page-y`/`card-spacing` 24→16px, `card-text-gap`/`button-gap` 16→12px — per the user's rule ("24px can afford to be 16px, 16px becomes 12px, 32px can go to 20px")
- **Deliberately left unscaled** (user's call, not an oversight): `text-icon` (4px), `card-row-gap` (48px), `radius-button`/`radius-card` (12px each) — "the rest keep as is". (`section-gap` did later get a *tablet+* variant — see Spacing above — but its mobile value is still the original 52px, untouched by this shrink-on-mobile mechanism.)
- `tracking-title` (`0.2em`) needs no override — it's an `em` unit, so it scales automatically with whatever `text-title` resolves to at each breakpoint

#### Homepage — icon row (`IconRow` component, `src/components/icon-row.tsx`)
- The icon+caption group as a whole is vertically centered in the gap between navbar and bottom text (`top: 50%` of that flex-1 space) on every breakpoint. It self-positions (absolute, `icon-row.module.css` `.wrapper`) rather than being positioned by a wrapper in `page.tsx`.
- **Responsive layout (tablet/desktop/large vs. mobile) — `tablet:` prefix applies at ≥768px, i.e. tablet AND everything wider, since Tailwind breakpoints are min-width by default; only mobile (<768px) differs:**
  - **Tablet/desktop/large:** icons in a horizontal row, caption below (fixed-height reserved slot, `h-6`/`leading-6`, so the group's height stays constant whether or not a caption is showing — the icons never shift).
  - **Horizontal positioning — went through three versions, currently back on v2:**
    1. Flat `left: 70%; translateX(-50%)`. Bug: at the 1024px desktop minimum, a 728px-wide 5×120px icon row centered at 70% had its right edge sitting *past* the viewport edge — overflowing off-screen. Only genuinely fit at viewports ≳1320px+.
    2. **(current)** `right: max(page-x, calc(30vw - half the row's width))`, fixed 120px icons (`ICON_SIZE_LG`) — caps the row so it never overflows, tracking 70% until it would violate the `page-x` margin, then holding flush against that margin instead.
    3. Tried making icon size fluid (`clamp(54px, calc(12vw - 38.4px), 120px)`, targeting `.hintTarget svg`) so the row could stay honestly centered at exactly 70% with no positional clamping at all, shrinking to avoid overflow instead. Built and shipped, but **the user preferred v2 and asked to revert** — so v3 (the fluid-size approach, and its supporting `ICON_ROW_WIDTH`/`ICON_ROW_GAP` removal) was undone. If this comes up again, v3's reasoning and formula are worth revisiting rather than re-deriving from scratch.
  - **Mobile:** icons stack top-to-bottom instead, size `ICON_SIZE_MOBILE` (72px), vertical gap between them via `gap-page-y` (`ICON_GAP_MOBILE` in `src/lib/icon-size.ts`, matches `page-y`, distinct from the 32px `ICON_ROW_GAP` used on tablet/desktop/large — mobile briefly used 0px gap before this), anchored `left: page-x` (32px from the left, not centered/right-anchored), still vertically centered as a group via the same `.wrapper` `top: 50%; translateY(-50%)` mechanism as tablet+ — centering is breakpoint-agnostic by construction, so resizing the icon/gap on mobile never needs a separate centering fix, it just naturally recenters around whatever the column's current height is. Detected via a small `useMediaQuery("(min-width: 768px)")` hook (`src/lib/use-media-query.ts`) rather than pure CSS, since the caption's position (below) needs real per-selection math in JS anyway.
  - **Mobile caption tracks the selected icon**, not the whole column: it's absolutely positioned to the right of the icon stack, vertically centered on *whichever icon is currently selected* (`top` computed from `selected index × (ICON_SIZE_MOBILE + ICON_GAP_MOBILE) + ICON_SIZE_MOBILE / 2`), so it visually sits beside that specific icon rather than at a fixed position.
  - **Bug fixed: `ICON_GAP_MOBILE` drifted out of sync with `--spacing-page-y` once mobile spacing tokens went responsive.** `ICON_GAP_MOBILE` is a plain JS constant (`16`, was `24`) standing in for the actual rendered `gap-page-y` between the stacked icon buttons, since the caption's `top` position is computed in JS, not CSS, and can't read a CSS custom property directly. It was originally set to `24` to match `--spacing-page-y`'s one and only value at the time — but once `--spacing-page-y` got a mobile-specific `16px` override (see Mobile token overrides above), the constant silently went stale, still assuming `24`. Each selected icon's caption ended up progressively more off-center the further down the stack it was (index × 8px error), which is why only *some* icons looked wrong rather than all of them. Fixed by updating the constant to `16`. This value has no way to auto-sync with the CSS token — if `--spacing-page-y`'s mobile override ever changes again, this constant needs a matching manual update.
  - **One line when it fits, wraps only when it doesn't, right edge caps at `page-x` (32px) from the viewport edge:** `width: max-content` (shrink to the text's natural single-line size) combined with `max-width: calc(100vw - iconSize - 2 × page-x)` — made explicit in code rather than relying on the implicit CSS shrink-to-fit algorithm absolutely-positioned auto-width elements get by default. **Bug fixed here:** the formula previously (wrongly) included an extra gap term as if the icon column's own width were `iconSize + gap` — it isn't; a vertical flex column's width is just its widest child (the icon), gap only affects the vertical axis. That extra term was over-subtracting space the caption was actually entitled to, which is exactly the kind of thing that would make it wrap more than necessary or fail to reach the intended right margin.
  - **24px gap reserved between the icon block and the bottom text, mobile only:** the icon row's positioning parent is inset by `page-y` (24px) at the bottom on mobile (`tablet:bottom-0` removes the inset on tablet+) — this shrinks the actual box the icon group centers within, which is what's needed for the reservation to work; adding *padding* instead wouldn't have worked, since an absolutely-positioned element's containing block includes its ancestor's padding as part of its size (the same subtlety noted for `px-page-x` earlier in this doc).
  - All hover/press/selection/discoverability-hint/crossfade animations are unchanged across breakpoints — only layout/position differs.
- 5 icons, left→right (top→bottom on mobile): chart line, boat, graph, leaf, shopping cart (Phosphor Icons, `regular` weight) — order and identity given directly by the user, not inferred
- Size: `ICON_SIZE_LG` (120px) on tablet/desktop/large, `ICON_SIZE_MOBILE` (72px) below that — both in `src/lib/icon-size.ts`. Default color: `icon` (#999999) via inherited `currentColor`
- Gap between icons: reusing `page-x` (32px) as a placeholder in both orientations (Tailwind's `gap-*` applies to whichever axis is active) — no exact value was specified, flagged for confirmation
- **Selection state:** default is **unselected** — no icon is active and no caption shows until the first click. Selected icon: **`content-secondary` color** (changed from `content-primary` — now matches "Si Min was @ Crypto.com"'s grey), persistent. Non-selected: `icon` gray, recolors to `content-secondary` on hover **only** on desktop + fine pointer (`(hover: hover) and (pointer: fine) and (min-width: 1024px)`), reverting on mouse-leave. Any icon, any device: press scales to `0.97x` (150ms, ease-out-quad), and click sets it as the new selection.
- **Click outside the row deselects** — resets to the default unselected state (no active icon, no caption), like dismissing a popover.
- **Caption:** type `caption` (Geist Medium 16px — its own token now that `nav` is back to 20px), color `content-primary` — assumed, no color was specified for the caption itself, flagged for confirmation. Text alignment tracks the selected icon's position: icons 1–2 → left, icon 3 → center, icons 4–5 → right, so the caption reads close to whichever icon triggered it.
- **Caption swap animation — chose crossfade over the user's proposed typewriter effect.** Consulted `/animate`: a character-by-character delete/retype for captions up to ~55 characters would run 2–3+ seconds combined, far past the "under ~300ms unless justified" guardrail, and this is a repeatable exploratory interaction (a visitor may click through all 5), not a rare one-time reveal — so the elongated wait would compound rather than delight. Implemented instead as `AnimatePresence mode="wait"` (old caption fully exits before the new one enters, since alignment shifts left/center/right per icon and overlapping under different alignments would look broken), spring `duration: 0.25, bounce: 0`, subtle 6px vertical hint + opacity (`framer-motion.md`'s "crossfade with a subtle directional hint" pattern). Reduced motion drops the 6px shift, keeping opacity-only.
- **Discoverability hint (idle animation) — loops for as long as nothing is selected.** Gating changed from "stop forever after the first ever click" to reactive on current selection state: the loop runs whenever `selected === null`, stops the instant an icon is clicked, and **resumes** if the user clicks outside to deselect back to the default state — matches "so long as the icons are in default state with nothing selected."
  - **Cadence matches the Scroll cue's** (deliberately, so the two idle animations on the page feel like one system): first pulse at 1.5s, repeating every 4s after that (`HINT_INITIAL_DELAY_MS` / `HINT_REPEAT_MS` in `icon-row.tsx`, mirroring the Scroll cue's `delay: 1.5`, `duration: 0.5` + `repeatDelay: 3.5`). Was 5s-then-every-8s before — shortened both because the user asked for parity with the Scroll cue's rhythm, and because a 5s wait made it easy to miss during normal back-and-forth testing.
  - Per icon: `scale: [1, 0.94, 1]`, 280ms, `easeOut`, staggered 50ms left→right. Reduced motion: opacity dip (`[1, 0.6, 1]`) instead of scale, same timing.
  - **Press-effect bug fix:** the hint animation had been targeting the `<button>` itself via `data-hint-icon`, and Framer Motion's imperative `animate()` writes its result as an inline `style` on that element — which permanently outranks the CSS module's `.iconButton:active { transform: scale(0.97) }` rule (inline styles always beat stylesheet rules for the same property), silently killing the press effect after the first hint played. Fixed by moving `data-hint-icon` onto an inner `<span>` wrapping the icon, so the hint's inline styles and the button's own CSS `:active` transform now target different elements and never conflict.
- Company names in each caption ("Crypto.com", "IBM", "EDB", "Univers", "NetVirta") are links, `link` color (#006FF9), pointing to the company's site (URLs given directly by the user). Open in a new tab (`target="_blank" rel="noopener noreferrer"`) — assumed default for external links off a portfolio page, not explicitly specified, flagged.

#### Homepage — hero sizing (`main` in `page.tsx`)
- **v1:** `flex-1` (grow to fill whatever space is left in `body`'s flex column). Broke once `WorkSection` was added as a sibling after `main` — flexbox shrank `main` to fit everything into one screen instead of reliably being a full first screen.
- **v2 (also wrong):** switched to `min-h-screen`, guaranteeing *at least* one viewport regardless of what follows — but this ignores that `Navbar` sits *above* `main`, not inside it. `min-h-screen` on `main` alone means hero+navbar together run to `navbarHeight + 100vh`, taller than one actual screen — which is exactly why "Si Min was @ Crypto.com" (pinned to the bottom of `main`) ended up sitting below the fold on first load instead of 24px above the true bottom of the viewport, as reported.
- **v3:** `Navbar` (`src/components/navbar.tsx`) measures its own rendered height via `ResizeObserver` and writes it to a `--nav-height` CSS custom property on `<html>` (defaulted to `0px` in `globals.css` for the brief pre-hydration window). `main` uses `min-height: calc(100vh - var(--nav-height))` — genuinely "fill the rest of the first viewport, however tall the navbar happens to be," robust to the navbar's height changing later and no longer coupled to whatever else follows in the DOM. This is why `Navbar` became a client component — it wasn't one before.
- **v3 still had a bug** (this is why the bottom text kept landing below the fold even after v3, on any window size): the `ResizeObserver` callback read `entry.contentRect.height`, but `contentRect` **excludes padding** — and the navbar's height comes almost entirely from its own padding (`py-page-y`, 24px top + 24px bottom), not its text. So `--nav-height` was being set to roughly just the 20px text's line-height, undercounting the navbar's true rendered height by about 48px — which made `main`'s `min-height` about 48px too tall, every single time, at every viewport size (hence "no matter how I resize"). **v4 (current):** the observer now reads `nav.offsetHeight` directly instead of `contentRect.height` — `offsetHeight` includes padding (and border), giving the navbar's actual full rendered height.
- Applied as an inline `style` (`minHeight: "calc(100dvh - var(--nav-height))"`) on `main` rather than a Tailwind arbitrary-value class, to remove any ambiguity around how Tailwind's bracket-notation parser handles spacing inside `calc()` expressions — not confirmed to be a problem in practice (Tailwind did normalize it correctly when checked), but there's no reason to depend on that when a plain inline style is just as easy and unambiguous.
- **Bug fixed: `100vh` → `100dvh` → `100svh`, mobile Safari scroll jank.** Reported on the live Vercel deploy, on-phone: scrolling past the hero caused the icons' apparent top/bottom spacing to suddenly jump, as if the whole hero briefly stretched.
  - **First attempt, `dvh` (dynamic viewport height), was insufficient.** `vh` is pinned to the *largest* possible viewport (browser chrome collapsed) regardless of what's actually visible, so it was the obvious first suspect — but `dvh` didn't fully fix it, confirmed on-device after deploying. The reason: `dvh` *continuously tracks* the current visible viewport, which means `main`'s height keeps actively recalculating in real time as Safari's toolbar collapses mid-scroll — that live resizing (of `main`, and therefore of `IconRow`'s `top: 50%` centering within it, in `icon-row.module.css`'s `.wrapper`) *is* the stretching effect, not a mismatch being corrected. Tracking the real viewport accurately doesn't help when the real viewport itself is changing mid-gesture.
  - **Fixed with `svh` (small viewport height) instead** — pinned to the *smallest* possible viewport (toolbar always accounted for as visible), so it never changes value as the toolbar shows/hides, and `main`'s height stays completely fixed throughout a scroll gesture. Trade-off: once the toolbar auto-hides and more space becomes available, that extra space just sits unused below the hero rather than the hero growing to fill it — a static, harmless gap instead of a live reflow. No fallback needed, same browser support tier as `dvh`.

### Motion
- Micro-interactions live on hover / press states
- Every animation gets documented here once implemented: trigger, duration, easing, and why it exists
- Must respect `prefers-reduced-motion`
- Interaction curves are gated by input capability (`hover`/`pointer` media features), not by breakpoint — a breakpoint can be touch-and-mouse-capable at once
- Durations / easing curves: `[PLACEHOLDER]` for anything not yet built; see Navbar above for the first documented example

## Responsive Behavior
- Breakpoints (mobile-first; base styles = mobile, no prefix needed):
  - Mobile: `< 768px` (default/base)
  - Tablet: `768–1023px` (`tablet:` prefix)
  - Desktop: `1024–1279px` (`desktop:` prefix)
  - Large: `1280px+` (`large:` prefix)
- Layouts should feel like variations of one system, not separate designs per device

## Future Extensibility
- Token structure should stay clean enough to support additional modes (e.g. light/dark) later without restructuring
